# Локальный граф утверждений

`fact_graph_nli.py` индексирует каждый непустой абзац, сохраняет предложения/фрагменты
с точными смещениями и сравнивает выбранные пары локальной Hugging Face NLI-моделью.
MNLI — задача сравнения, а не модель извлечения всех атомарных фактов. Узлы этого
графа — дословные утверждения-кандидаты, включая сложные предложения; субъекты,
местоимения, причинность и истинность автоматически не устанавливаются.

```sh
cd /Users/artemk/projects/NovelGenerator
python3 scripts/fact_graph_nli.py --chapters runs/nora-author-facts-deepseek1 --out runs/nora-nli-new --cache-dir /private/tmp/novel-nli-cache --local-only
```

`--file input.txt` анализирует один файл, `--text '...'` — строку. По умолчанию язык
выбирается по буквам; `--language en|ru` задаёт его явно. Английская модель:
`cross-encoder/nli-deberta-v3-base`; русская:
`cointegrated/rubert-base-cased-nli-threeway`. Метки читаются из конфигурации; для
неизвестного чекпойнта с непрозрачными метками нужен явный `--labels` в правильном
порядке логитов. Никакие рукописи в API не отправляются.

Зависимости перечислены в `requirements-fact-graph.txt`. В текущем окружении они
уже доступны; отдельная установка возможна в виртуальном окружении. Модели для
проверки скачаны в `/private/tmp/novel-nli-cache`. Без `--local-only` недостающие
веса загружаются с Hugging Face. Стандартный кеш скрипта — `runs/hf-nli-cache`.

Выходной каталог должен быть пустым:

- `sources.json`: все абзацы, фрагменты, исходные пути, смещения в символах Python,
  номера строк и SHA-256 исходных файлов;
- `report.json`: модель, ревизия, метки, параметры, покрытие, оценки, кандидаты;
- `graph.graphml`: исходные абзацы → фрагменты → лексические упоминания, плюс NLI-связи;
- `view.html`: автономный просмотр пар с полными исходными абзацами, без внешних библиотек.

Поиск использует глобальный лексический индекс, а не только соседние фразы.
`--entities Nora,Claire,key` добавляет подсказки для поиска. `--neighbors` ограничивает
число соседей, `--max-pairs` — число уникальных пар. Каждое направление считается
ровно один раз. Слишком частые слова пропускаются при поиске; поэтому полнота
поиска не гарантирована. `--extract-only` сохраняет индекс без оценки согласованности.

Сначала сохраняются все буквальные NLI-противоречия. В короткий список для проверки
попадают пары с высоким противоречием в обоих направлениях, общим лексическим
упоминанием и совместимыми эвристическими метками источника, времени и аспекта.
Реплики, воспоминания, разные явные моменты времени и разные известные аспекты
остаются доступны в полном списке. Эти фильтры могут ошибаться и пропускать настоящие
ошибки: это сортировка материала, а не проверенная логика мира.

Ни один кандидат не объявляется ошибкой автора. Баллы — softmax модели, а не вероятность
ошибки книги. Длинные пары не обрезаются: они отмечаются как непроверенные. Отсутствие
связей, достижение лимита или пропуск пары не означает, что книга согласована.

Проверка:

```sh
python3 -m unittest discover -s tests -p 'test_fact_graph_nli.py' -v
```

В живом английском демо 12 буквальных срабатываний после сортировки дали два кандидата
прямого отрицания; в русском — три срабатывания и один кандидат. На книге о Норе:
223 абзаца, 706 фрагментов, 7264 направленных сравнения, 1538 буквальных срабатываний
и 75 кандидатов. Время локальной проверки — около 86 секунд на MPS. Многие даже из
75 кандидатов относятся к разным сценам, поэтому этот результат не измеряет число
ошибок. Исходные оценки сохранены в `report-before-triage.json`; сортировка пересчитана
из них локально, без новых вызовов модели.
