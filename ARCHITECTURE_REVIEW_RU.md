# Повторный аудит генератора — 8 сентября 2026

Аудит текущего кода и сохранённой трёхглавной рукописи. Коммерческий успех книги нельзя подтвердить архитектурой или оценкой модели. Ниже — проверяемые результаты, ограничения и выполненные исправления.

## 1. Карта архитектуры

| Модуль | Назначение | Вход → выход | Статус |
|---|---|---|---|
| `contracts.ts` | Фиксированный авторский контракт | Настройки → BookSpec | Реализован |
| `engine.ts`: outline/plan | Конфликт, персонажи, обещания, сцены | BookSpec + утверждённый план → blueprint и планы глав | Реализован, содержательность проверяет модель |
| `writer.ts` | Написание сцен двумя способами | План + предшествующий канон → кандидат прозы | Реализован; сравнение качества требует читателей |
| `review.ts` | Проверка и извлечение фактов | Полная глава → замечания и цитаты | Исправлено принятие непроверенных результатов |
| `storyState.ts` | Канон и зависимости версий | Принятая проза + подтверждённые цитаты → StoryState | Исправлена инвалидизация и выбор кандидатов |
| `engine.ts`: globalReview/lineEdit | Структурная и адресная редактура | Реестр фактов и замечания → новые версии → повторная проверка | Ограниченные циклы, без автоматического принятия по исчерпанию попыток |
| `runStore.ts` | Сохранение и возобновление | Состояние запуска ↔ IndexedDB | Версии сохраняются; отдельная сессия браузера имеет отдельное хранилище |
| `presentation.ts` и React | Интерфейс и экспорт | Снимок запуска → главы, статусы, итоговая книга | Незавершённые кандидаты блокируют финальный экспорт |
| `ollamaService.ts` | Доставка ответа модели | Запрос → завершённый поток | Ошибки, обрыв и лимит токенов не считаются успехом |

Поток: настройки → утверждение общего плана → blueprint → планы глав → сцены → кандидат главы → проверка → извлечение подтверждённых фактов → принятие → следующая глава → структурная проверка → адресная редактура → финальная проверка → экспорт. После изменения ранней главы поздние главы проверяются повторно.

## 2. Логические проблемы

- В прежней обработке редакторских ответов некорректный JSON мог превращаться в пустой список замечаний. В `review.ts` теперь используется `not_checked`, а неподтверждённые цитаты вызывают отказ в приёмке.
- Исчерпание попыток исправления могло приводить к принятию неудачной главы. `engine.ts` останавливает процесс для редакторского вмешательства; `storyState.ts` отдельно проверяет условия принятия.
- Принятый статус скрывал более новый неудачный кандидат. Выбор следующей главы и финальный экспорт теперь учитывают незавершённые кандидаты.
- Прежние checkpoints содержали статусы, полученные более слабой проверкой. Миграция сохраняет прозу и версии, но требует повторной проверки.
- В потоковом ответе Ollama необходимо проверять ошибку, завершающую запись и причину остановки. Эти проверки добавлены; fallback разрешён только при неподдерживаемом endpoint.
- На выбранной модели GLM служебный текст попадал в канал содержания при `think:false`. Живой протокольный тест подтвердил разделение каналов при `think:true`, но по последующему прямому требованию автора thinking отключён для всех моделей и этапов. Защита от служебного текста остаётся в проверке структурированного вывода. Проза дополнительно возвращается в отдельном поле JSON.

## 3. Разрывы относительно литературного качества

Все девять исходных критериев теперь присутствуют в заданиях планировщика и редакторов, но наличие задания не доказывает качество результата.

| Критерий | Поддержка | Что остаётся проверять редактору |
|---|---|---|
| Сюжетная арка | Планы и изменение героя | Причинность и убедительность переходов |
| Центральный конфликт | Явное поле blueprint, ставки и последствия | Достаточность сопротивления и цены выбора |
| Темп и структура глав | Планы сцен, локальная и глобальная проверка | Ритмическое разнообразие, отсутствие затянутости |
| Глубина персонажей | Желание, потребность, противоречия, отношения | Индивидуальность и психологическая правдоподобность |
| Диалоги | Речевые привычки, адресная редактура | Подтекст и различимость голосов |
| Стиль и голос | Язык, POV, время, тон, стилевые настройки | Устойчивость голоса и оригинальность образов |
| Эмоциональные крючки | Выбор, цена, последствия, начало сцены | Реальный читательский интерес без шаблонных клиффхэнгеров |
| Концовка | Обязательные обещания и свидетельства развязки | Эмоциональная заслуженность финала |
| Целевая аудитория | Поле контракта и редакторская проверка | Соответствие конкретным читателям, проверяемое чтением |

В сохранённых черновиках обнаружены конкретные дефекты: английские рабочие заметки среди прозы, реплика с личным воспоминанием Ильи, ошибочно отданная Вере, и оборванный вариант третьей главы. Первая глава очищена от служебного вступления. Структурная проверка выявила ещё два разрыва во второй главе: необъяснённый ранний приход Веры и исчезновение конверта после передачи Илье. Они исправлены точечно и привязаны к новым точным цитатам. Все три главы приняты в ревизиях 9/8/8; структурная и финальная проверки прошли, итоговый экспорт создан. Thinking отключён на всех этапах. GLM оставлена для прозы, а структурированный контроль выполняет локальная Granite, прошедшая capability-test JSON Schema.

Системное ограничение: точное совпадение цитаты доказывает наличие фрагмента, но не правильность интерпретации. Глобальный редактор работает с реестром свидетельств; отдельные главы проверяются полностью. Межглавные стилистические повторы и тонкие психологические противоречия могут остаться незамеченными.

## 4. План исправлений

1. **Высокий — выполнено:** закрыть ошибочную приёмку, отделить служебный вывод, сохранять все версии и повторно проверять зависимости. Эффект: не выдавать известный дефект или непроверенный текст за готовую главу.
2. **Высокий — выполнено:** завершить живую повторную проверку трёх глав, проверить обязательные развязки и итоговый экспорт. Это проверка реальной интеграции, а не гарантия литературного успеха.
3. **Средний — реализовано:** адресные исправления по цитируемым замечаниям вместо сплошного переписывания. Эффект: лучше сохраняются удачные места и авторский голос.
4. **Средний — инструмент реализован, оценка открыта:** сравнивать два способа письма на одинаковом контексте с отдельными образцами и слепой читательской оценкой. По одной паре нельзя выбирать победителя для всех книг.
5. **Средний — постоянная редакторская работа:** оценивать готовый текст целиком, особенно знания персонажей, цену решений, повторяемость образов и эмоциональную развязку.

## 5. Быстрые победы

- Сохранять удачные версии; не увеличивать бесконечно число автоматических переписываний.
- Разделять технический результат проверки и читательскую оценку текста.
